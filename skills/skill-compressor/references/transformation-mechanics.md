# Transformation mechanics

Use this reference while classifying and rewriting one skill seam.

## Highest-confidence transformations

1. Delete exact duplication and keep one canonical owner.
2. Replace repeated records with stable-ID references to one ledger.
3. Move genuinely conditional schemas, examples, procedures, or domain material to
   a routed reference with a precise read condition.
4. Merge synonymous rules while preserving their distinct activation conditions.
5. Replace enumerations with a generative decision test when distractor cases prove
   the abstraction selects correctly.
6. Remove restated model defaults only after a no-guidance control ties on positive,
   negative, and compounded cases.

## Risky transformations

- Deleting thresholds, permissions, authority boundaries, stop conditions, or failure
  states because they look obvious.
- Moving a required invariant behind a route the model may not take.
- Compressing examples that are the only specification of an operational rule.
- Replacing an executable algorithm with an adjective such as “carefully,” “deeply,”
  or “appropriately.”
- Shortening the description until catalog routing loses recall or precision.
- Improving one exposed fixture with vocabulary that does not transfer.

## Seam-wise delta debugging

Partition the candidate text by behavior-changing seam, not arbitrary line count.
For each seam, consider unchanged, removed, and minimal replacement; execute viable
variants through the evaluation protocol. If removal fails,
split the seam by activation condition or owned decision and test again. Restore the
smallest failing atom. Re-run cross-seam and compounded cases after each accepted
batch because individually safe removals can interact.

The final ledger records `KEEP`, `CUT`, `MERGE`, `MOVE`, `SHARPEN`, or `UNRESOLVED`,
with the experiment and affected quality cells supporting each verdict.
