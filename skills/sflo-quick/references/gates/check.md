# CHECK

Produce `CHECK.md` as the sole home for observed evidence. For each candidate, run objective proofs in clean processes; use a fresh non-builder evaluator for judgment-dependent criteria. Record which separation was used. Supply FRAME, the named candidate, declared work products, and necessary environment; keep MAKE claims outside that context until observations and verdict are recorded.

Name the MAKE candidate under examination and group its evidence by candidate ID. Record the verification context, materials supplied and excluded, and execution isolation. For every FRAME criterion, record the command or action, observed result, evidence location, and `pass`, `fail`, or `blocked`. Run the planned proofs and add one verifier-chosen probe targeting the riskiest plausible false-positive or failure mode. A rerun supersedes earlier evidence only for the same candidate and named proof.

Match proof to the work: execute behavior, query and reconcile data changes, exercise interactions, and inspect rendered or produced outputs. Use a clean process when hidden state could alter an objective result. Give judgment-dependent criteria a fresh evaluation context; when none is available, mark them blocked instead of self-certifying.

CHECK passes when every material criterion has direct evidence, required judgment has independent evaluation, and targeted falsification leaves no unresolved material failure.
